# Demo video plan (3 minutes)

Draft. Update it when the app is final. Record on a phone-size screen.

Judges score: Impact 30%, Meta tooling 25%, Demo 25%, Technical depth 20%.

## Story in one line

A local business owner runs the whole booking business by talking to it.

## Script

| Time | Show | Say (short) |
| --- | --- | --- |
| 0:00 | Home page, type a business name | "Any local business can start in one minute." |
| 0:20 | Pick it, log in, the page is built | "Meta's model builds the page from the business's Google Maps data." |
| 0:45 | The public page, then the Spanish page | "Customers book here, in English or Spanish." |
| 1:05 | Owner area, then tap the chat tab | "The owner has an assistant that works for them." |
| 1:15 | "What is on today?" | Steps appear: it looks up real data. |
| 1:35 | "Add a service Haircut, 30 minutes, 25" | It creates it. Show it in Services. |
| 1:55 | "Book Ana for a haircut tomorrow at 10" | It checks free times, repeats the details, shows a card. Tap Confirm. |
| 2:25 | "Cancel Ana's booking" | A card appears first. Nothing changes until the tap. Tap Confirm. |
| 2:45 | Say the safety points | "It can never double-book. Risky actions always need a tap. Every change is logged." |
| 2:55 | End on the chat | Name, one line, done. |

## Points to say out loud

- Uses Meta Muse Spark through the Meta Model API: tool calling, streaming, reasoning.
- It acts, it does not only chat: it reads data, books, edits and cancels with the app's own rules.
- Safe by design: the owner taps before anything risky, and the server (not the model) writes what the card says.
- Everything in the repo was built during the hackathon (first commit Oct 26).

## Before recording

- Use a clean demo business with 2 services and 1 team member.
- Test every line of the script twice, the model can answer differently.
- Dark or light mode, pick one and keep it.
- Phone-size window, notifications off.
